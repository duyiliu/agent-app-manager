# Worktree 与端口流程

多 worktree 并行、隔离启动或端口冲突时读取。Skill 负责依据项目证据选择端口并生成启动描述，现有 manager 保存和执行描述；本流程没有新增 CLI 参数、注册表字段、端口锁或原子分配能力。启动、停止、构建和项目文件修改仍遵守 `SKILL.md` 的授权范围。

## 1. 匹配当前实例

- 用户明确指定的应用别名/ID/路径优先，先核对其登记再操作，保留从任意目录管理指定应用的能力；manager 引用只接受别名/appId，用户给出路径时先按真实 `root` 经 `list` 解析到对应登记再操作。以下“当前 worktree”用于用户要求启动当前项目或未另指目标的情况。
- 在目标目录用 `git rev-parse --show-toplevel` 确定 worktree 根，再解析真实路径；非 Git 项目采用已确认的项目根。`root` 是当前 worktree，`cwd` 是其启动模块；不能把 Git 公共目录或主 worktree 路径当作当前根。
- 使用同一管理数据目录（通常默认目录），通过 `--json list` 按真实 `root` 筛选，再用 `--json status <appId>` 核对 `entry`（列表不返回入口）。应用身份沿用 manager 的真实根路径＋入口规则，Windows 按大小写不敏感比较。不要因换分支改应用身份，也不按仓库名或别名猜实例归属。
- 已登记时保留别名和配置；新登记别名需满足全局唯一、最长 32 字符及现有字符约束。可用项目/目录可读片段加真实路径的短哈希，截断可读部分；分支名只作可选展示，不作为唯一性保证。`ALIAS_TAKEN` 时重新查登记并调整，不能覆盖他人的别名。
- 当前实例核验为 RUNNING 时复用（明确重启除外）；STARTING/UNKNOWN 保留证据并按 manager 恢复规程处理；BACKOFF 仍可能重启，不能当成已停止的空闲实例；非受管实例不能据端口冒充受管。其他 worktree 的存活实例只作冲突证据。

## 2. 选择并传入端口

| 条件 | 行动 |
|---|---|
| 用户明确指定端口，或项目要求固定端口 | 冲突即报告占用和阻塞，不自动换端口 |
| 当前登记端口可用 | 优先复用保存的配置和端口 |
| 首次登记且项目默认端口可用 | 使用已确认的默认端口 |
| 历史/默认端口冲突，且属于多 worktree 或已授权隔离运行 | 确认项目支持的覆盖入口和关联地址，再选择空闲候选 |
| 普通非隔离启动、覆盖入口不明或关联地址无法同步 | 报告阻塞，不猜参数、不改项目文件绕过 |

候选优先取项目已有开发端口范围；没有范围时从历史/默认端口之后有界寻找有效端口（1–65535，建议最多检查 20 个候选）。先用 `--json list` 参考其他登记应用的预期/实际端口，尽量避开其声明值，再用 `--json port <N>` 检查真实监听；`list` 的 `actualPorts` 仅在端口枚举成功且实例核验为 RUNNING 时出现，缺失或为空不代表端口空闲。登记值是避让线索，不是永久预占；范围用尽或探测失败时报告，不把未知当空闲。主服务、独立管理接口、调试、HMR 等已启用监听分别核对，不为未启用能力额外分配。

- 阅读项目脚本/源码、当前依赖版本的 CLI 帮助，确定参数转发和优先级。覆盖端口写入直连 `args`、命令模式 `command` 或项目实际读取的 `env`，不假定所有服务都读取 `PORT`。
- 同步设置 `expectedPort` 与指向该服务的 `readyUrl`；保留原有路径、协议和其他必要配置。只改 `expectedPort` 不会改变服务监听。留意脚本内部字面值、配置文件或命令行参数覆盖环境变量的情况。
- 不改受版本控制的配置、脚本或共享 `.env`；本地覆盖文件也需项目支持且在已有写入授权内。描述中的 `env` 只放非敏感值，密钥沿用 `envRefs`/`envFile`，不复制进新描述。
- 只使用已有接口：新登记用 `start-new --desc <file>`；未变配置用 `start <ref>`。已停止实例需更换端口时，在保留当前完整配置的基础上更新端口相关字段，沿用相同 `root`/`entry`/别名，通过 `start-new --desc <file>` 重建同一应用登记；不要直接编辑 registry/runtime，也不要臆造 `start --port`、`--auto-port` 等参数。活跃或未结实例先遵守原启停/恢复规程，不换别名再起一份。
- 重建描述优先使用与当前登记一致的完整描述；缺失或过期时只读当前数据目录的 registry，在本地按 desc 允许字段和当前启动形态提取启动配置（包括环境引用、依赖、就绪、重启策略、日志、退出回调和 `x-` 扩展），排除 `appId`、配置修订和时间戳等登记元数据。desc 允许字段以 `scripts/lib/desc.mjs` 的 `loadManagedDesc` 归一化键集合为权威；登记备份 `export` 的字段清单与之对齐，但导出会对敏感名 `env` 键脱敏、`envRefs` 只导名称，不能当作完整配置恢复源。仅对校验器允许为空的可选字段，缺省或 `null` 按归一化规则取默认值（如 `entry=default`、`cwd=root`、`restartPolicy=never`）；必填字段、`x-` 扩展不套用此规则。已有配置逐项保留，不把未取到的字段当缺省重置；非 Java 应用保留明确的 `mode`，避免回落默认 `java`。命令模式须省略 `args`（登记中归一化出的空数组也不能直接回填），直连模式不带仅适用于命令模式的 `expectedImage`/`discoverTimeoutMs`。不要直接将整条登记作为 desc，也不要从经过脱敏/截断的 `status.env` 重建环境值；源配置不完整时停止。保留原有敏感值引用，避免在聊天或命令输出中回显。

## 3. 同步调用关系

先确定本 worktree 后端端口，再使用项目已有环境变量或配置覆盖入口设置其前端代理/API 地址、测试 base URL 和健康检查地址，最后启动调用方。浏览器相对路径 `/api` 只有在当前前端代理确实指向该后端时才算完成联动。依赖登记应指向当前 worktree 的对应应用；只有项目明确约定的共享服务才跨 worktree 复用。

核实 API 地址是启动时读取还是构建时固化，需要重启/构建时遵守原授权；回调白名单、CORS 或远程配置不能本地覆盖时，说明具体阻塞。不要改共享后端、数据库或远程设置。多服务编排优先拆为可独立核验的启动描述，不因指定多个端口就假定能发现唯一受管进程。

## 4. 启动、验证与竞争

1. 启动前再查目标登记和端口，按 manager 规程执行并保存端口参数；不使用 `--force`、降低 `expectedPortConfidence` 或删运行记录绕过冲突。
2. 通过 `status <ref> --probe --ready` 核验受管身份、实际监听与就绪，必要时结合 `port <N>`、本批次日志和平台进程证据。`actualPorts` 只枚举目标 PID；受管目标身份以 `status <ref>` 的 `run.pid`+`creationFileTime`+`image` 为准，占用者以 `port <N>` 返回的 pid 与 `identity`（创建时间/映像）逐字段比对；仅在 `identity.result=ok`、身份证据完整且一致时确认归属，缺失值不能据相等认领。不依赖命令行识别身份，也不外传或回显可能敏感的进程数据。manager 未提供只读的父子关系枚举（`stop --tree` 是终止操作而非只读核验）；监听者既非受管目标、又无法取得与目标后代关系的证据时，停止并报告“端口归属未验证”，不认领、不停止、不据此重试换端口。
3. 自动顺延的实际端口必须重新核对归属及关联地址；不要只取第一个监听端口或只改 UI 链接就宣告成功。进程存活、端口归属、业务就绪分别报告；对当前范围内的前后端还需验证代理/调用目标对应当前 worktree，未检测项明确标出。
4. 端口检查与应用绑定之间仍有竞争。仅在明确的端口竞争、允许自动换端口且已确认本次尝试的目标和 wrapper/服务后代均无残留、无未结记录时，重新选端口并更新完整描述；包含首次启动最多 3 次。其他错误不按端口问题重试，`READY_TIMEOUT` 可能仍有 RUNNING 进程，不直接再起。
5. `ALREADY_RUNNING` 时重新核验当前登记，符合当前根/入口与启动意图则复用；UNKNOWN/身份不明或残留按 manager 恢复规程处理并停止端口重试。用户固定端口的请求始终不自动换端口。

交付当前 worktree、别名、业务访问地址、所用端口覆盖方式及核验结果。跨会话 `start/restart` 复用保存的参数；管理台共用一份，不按 worktree 另起 UI 或隔离 `--home`。本流程减少冲突但不保证多个 Agent 并发选择时端口唯一。
